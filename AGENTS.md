# AGENTS.md

Restora — smart restaurant management. React 19 + Vite + Tailwind v4 frontend; optional Express 5 + `better-sqlite3` backend. Plain JS/JSX, ESM only (`"type": "module"`) — there is **no TypeScript and no build step for the server**.

The design source of truth is `docs/superpowers/specs/2026-10-12-restora-ux-design.md` (plan: `docs/superpowers/plans/`). `README.md` §"Build tracker" maps modules to steps.

## Commands

```bash
npm install
npm run dev        # Vite demo on :5173, localStorage, no backend needed
npm run build      # → dist/
npm run server     # Express + SQLite API on :3001 (serves dist/ if built)
npm run seed:demo  # idempotent full demo (both stores + a login per role)
npm test           # node --test over tests/**/*.test.js
npm run lint       # oxlint (warnings tolerated; only no-undef is an error)
node --test tests/units.test.js   # run one test file
```

No typecheck. Verification order: `lint` → `test`.

## Architecture — read this before changing state

- **`src/lib/reducer.js` is the single source of truth and runs on both sides.** The client (`src/lib/store.jsx`) and the server (`server/index.js`, `server/db.js`, `server/telegram.js`, `server/ai.js`) import the *same* reducer. Every state change must be a new action dispatched through it — never mutate state elsewhere, or the server/SSE terminals diverge.
- State is an "empire": `{ version, locations: { downtown, riverside } }`. Shop actions travel wrapped as `{ type: 'LOC', locId, action }`. `STATE_VERSION` is `6` (server schema is v3); old snapshots/DBs migrate on boot in `reducer.js` `migrateToEmpire` and `server/db.js`. Bumping a version means adding a migration, not just changing the number.
- The server imports helpers from `src/lib/**`; the Dockerfile ships both `server/` and `src/` for this reason. Keep them ESM-compatible and safe to import in Node (no browser globals at module top level).
- **Multi-tenant:** every state table, action log, and SSE stream is partitioned by `owner_id`. Tenant per request: signed-in user → own owner; super admin → `?ownerId=`; guests/mini app → `?owner=<slug>`. Don't write cross-tenant reads.
- **Online-only: there is no offline lane.** A dispatched shop action is applied locally *only* in the moment the server takes it — the store POSTs it, and a refusal/failed POST routes through `resync()` (server snapshot wins, the local edit is dropped). While the link is down (`offlineNow()` in `store.jsx`: server mode with `status !== 'live'`, or a whole-terminal outage — `hasSeenServer()` reads the `restora-server-seen` marker and distinguishes that from the pure `npm run dev` demo) every dispatch is refused with a plain-English notice: nothing applied, nothing queued, no conflict records, no `src/lib/offline.js` gates. The localStorage demo (no server on record) still edits in place — it has nothing to sync to. What stays: every action carries a client-unique `_lid`, the server dedupes a retried POST by `(owner_id, client_id, lid)` (`server/db.js` `findDuplicateAction`; the `actions` route returns `{ seq, dedup: true }` without re-applying) and the SSE echo of a terminal's own action is skipped via `lidAt`. Offline sign-in comes from the cached `/api/auth/me` in `src/lib/auth.jsx` (`restora-session-cache-v1`, 24h TTL; cleared by logout or an explicit server "not signed in").
- **Branch assignment pins a user to one shop.** `auth_users.location_id` (nullable = every branch) is validated against the tenant's live snapshot in `server/auth.js` (`readBranchAssignment`, `buildEmpire()` fallback before the first snapshot) and set from Users → Branch. `resolveTenant` turns it into `req.scopeLocationId`: `/api/state` ships only that branch (switcher/tabs/All-branches self-collapse), `/api/menu` + every `resolveLocation` route 403 another `loc`, `/api/actions` accepts only that branch's `LOC` (empire-level actions 403), `server/ai.js` `shopFor` clamps to it, and both SSE broadcast and replay (`eventInScope`) filter by it. A removed branch silently unpins (never bricks); owners/super admins/guests are never pinned. Migration adds the column in place; `AppShell` disables the switcher when a terminal sees one branch.
- **Not-counted inventory** is `counted: false` on items (`normalizeInventoryItem`, default true; no `STATE_VERSION` bump). Count sheets, `stockStatusFor` (neutral `'not_counted'`), `applyAuto86`, sale decrements, `movementSummary`/`stockFlow`/shift reports, `stockValue()`, variance/negative-stock docs, and exception lists skip them — but receiving a purchase still adds stock + cost, so their on-hand only grows. Toggle lives in `IngredientModal`; `tests/not-counted.test.js` is the regression net.
- **Money** is stored as plain numbers in the base currency and formatted only via `src/lib/currency.js`; normalized menu prices in SQLite are integer cents. **Unit arithmetic** (`packFactor`, `packPrice`, `describeQty`, …) lives only in `src/lib/units.js`.
- **i18n:** UI supports km/en/zh. Strings are auto-translated through `src/lib/i18n.js` + `src/lib/i18n-phrases.js`; add phrases there instead of hardcoding translated text. The Kitchen display has its own dict in `src/lib/kitchen-i18n.js` and defaults to Khmer.
- **AI is optional and read-only.** `server/ai.js` exposes `/api/ai/{status,chat,insight,briefing}` around a provider-agnostic adapter (`src/lib/ai-providers.js`) and a redacted context digest (`src/lib/ai.js`); the browser calls them through `src/lib/ai-client.js`. No `AI_API_KEY` ⇒ every route is a 503 no-op and the app is unchanged. Guests are pinned to `scope:'menu'`, the model never dispatches a reducer action, and replies are cached per context hash. Prompting lives in `src/lib/ai.js`: the guest `scope:'menu'` digest is the rich row (localized names, `dietaryTags`/`allergens`/`spiceLevel`, ingredient names only — never quantities/costs, plus a `popular` flag from real sales) and uses `SYSTEM_PROMPTS.menuBase` for recommendation-first answers; ops adds `SYSTEM_PROMPTS.appGuide` so "how do I …" questions can be answered. Guests hitting `/api/ai/status` get no server stats, and guest rate-limit buckets are per-IP (`actorKey`). Surfaces: the Ops Copilot screen (`src/screens/Assistant/`), the dashboard AI cards (`src/screens/Dashboard/sections/{AiInsight,ShiftBriefing}.jsx`), and the guest/mini-app concierge (`src/components/MenuConcierge.jsx`). Env vars: `AI_API_KEY`, `AI_PROVIDER`, `AI_MODEL`, `AI_BASE_URL`, `AI_TIMEOUT_MS`, `AI_RATE_LIMIT`, `AI_GUEST_RATE_LIMIT`, `AI_RATE_WINDOW_MS`, `AI_CACHE_TTL_MS` (see README).
- **Per-tenant AI config (owner/super-admin only).** `server/ai-config.js` adds `GET`/`PUT /api/ai/config` and `POST /api/ai/config/test`; the UI is **Settings → AI assistant** (`src/screens/Settings/sections/Ai.jsx`). Config lives in the SQLite `kv` table (`getAiConfig`/`setAiConfig` in `server/db.js`) — **never** in reducer state, because `/api/state` is served to guests. `mergeAiConfig(stored, env)` (exported from `server/ai.js`) lets tenant fields override env with per-field fallback; the raw key is write-only (`present()` reports `hasKey`/`keySource`, never the key). Changes apply on the next request, no restart.
- **Deployment branding is instance-wide, never reducer state.** `server/branding.js` adds `GET /api/branding` (public — the sign-in screen is anonymous) and `PUT /api/branding` (super-admin only; `requireSuperAdmin` is exported there and mounted in `server/index.js`). Values live in the SQLite `kv` table under a reserved platform owner (`getBranding`/`setBranding` in `server/db.js`). `src/lib/branding.js` caches the public fetch in module scope (no React provider), paints the browser chrome (title, favicon, `apple-touch-icon`, dynamic web manifest), and exposes `useBrand()` to `AuthScreen`, `AppShell`, and the boot screen; the editor is **Settings → App brand** (`sections/Brand.jsx`), shown to super admins only. Logo = wide mark (sign-in/boot screens); icon = square mark (sidebar badge, browser tab, home screen); clearing either restores the built-in defaults. Restaurant-level name/logo stay tenant settings for documents and the guest menu.
- Guest surfaces (`GuestScreen`, `MiniAppScreen`) render with `<RestoraProvider waitForServer={false}>` so the menu paints before the network answers; only logged-in terminals wait on a boot screen.
- **Floor plan geometry is per-branch shop state.** `state.floor = { roomW, roomH }` (px per axis; `0` = auto-fit the viewport) and `state.floorZones = [{ id, name, x, y, w, h }]` (percent rects). `table.zone` stays the assignment string; `SET_TABLE_LAYOUT` also carries an optional `scale` → `tileScale` (0.75–3) for the tile footprint. Legacy snapshots get zones seeded once from the old derived auto-bands (`seedFloorZones`) so upgrades redraw identically; renaming (`UPDATE_FLOOR_ZONE`) reassigns its tables and `DELETE_FLOOR_ZONE` falls them back to `'Main'` — tables never vanish with a zone. Arrange-mode UI lives in `src/screens/Floor/sections/FloorMap.jsx`; all flows dispatch through the reducer, so SSE and outbox replay work unchanged.

## Tests

- `node --test` with `node:assert/strict`; files in `tests/*.test.js`. No Jest/Vitest.
- Server tests (`auth-server.test.js`, `tenant-isolation.test.js`, `demo-seed.test.js`, `menu-catalog.test.js`) point `RESTORA_DATA` at an `os.tmpdir()` scratch dir before importing `server/*`. Always set `RESTORA_DATA` for test writes — never touch `server/data/`.
- UI tests (`screens-ui.test.js`, `tabs-ui.test.js`, `screens-contract.test.js`, `multitab-ui.test.js`, `telegram-ui.test.js`, `miniapp-seating.test.js`, `assistant-ui.test.js`, `dashboard-ai.test.js`, `guest-concierge.test.js`, `online-only-ui.test.js`, `floor-edit-ui.test.js`) boot Vite via `createServer({ server: { middlewareMode: true, hmr: false } })` in jsdom, then `ssrLoadModule`. Reproduce this setup when adding a UI test — without `hmr: false`, concurrent UI tests collide on the HMR port. The AI/guest UI tests stub `globalThis.fetch` so `/api/ai/*` answers without a server; `online-only-ui.test.js` stubs fetch to throw (production terminal, `restora-server-seen` preset) to prove while-down dispatches are refused and never queued, then swaps in a live stub — it must unmount the provider in `after()` or the reconnect interval keeps the process alive.
- Each `src/screens/*Screen.jsx` should keep a heading the contract test can find; `ROLE_NAV` / `NAV_SECTIONS` in `src/lib/constants.js` drive both sidebar and tab strip and must not drift.

## Operational gotchas

- The root `.env` is a **stale leftover** from a Postgres/Spring Boot template and is never loaded (no `dotenv`). Real config is `process.env` only: `PORT`, `HOST`, `RESTORA_*`, `TELEGRAM_*`, `SUPERADMIN_*`, `AI_*` (see README).
- `server/data/` (SQLite) and `dist/` are git-ignored. In Docker the DB lives on the `restora-data` volume — seed it with `docker compose exec restora npm run seed:demo`, not from the host.
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `style:`), often with a scope (`feat(tenant): …`).
